# Verification evidence — manifest

Curated, tracked captures of the implemented product after the Hi-Fi redesign (`docs/design/hifi-decisions.md` §10), Stage B (§11: the populated Food tab, device record, local icons and app icon) the R1–R6 revision (§12: selected days, streak and goal history on Home; curated recipe discovery; the two-step manual task with the shared exit policy; source-specific review; the R6 method sheet) and revision H2 (§13: the compact day strip, the calorie card and macro cards, the recommendation above the meals, the targets sheet with its estimate path, the adjustable water reference, Recipes discovery without a search field, the shared Search toolbar in both scopes). Every image was rendered by a script from the committed source and then read at full resolution; the “Inspection” column is that reading, not an automated result. The complete local sets (70 runtime + 176 Storybook images) are regenerated into the ignored `.verification/` directory by the same scripts.

- Source state: the H2 checkpoint on `feat/redesign-home-recipes-targets` (the commit that updates this file); every image below was rendered from that tree. Rows whose composition H2 changed (every Home row, Recipes discovery, Search in both scopes, the recipe filter sheet now opened from Search) were re-read and their notes rewritten; the rest were replaced by pixel-near re-renders of the same states. Retired with this revision: `02-goal-sheet.png`, `32-recipes-browse.png`, `35-recipes-filtered.png`, `43-home-recommendation-with-filters.png`, `19–23-budgetbar-*.png` and `39-goal-editor-targets.png` (replaced by the daily-nutrition and targets rows below). Retired rows and their files: `O05-add-to-meal-food.png` (foods now commit on the review screen; the Add-to-meal sheet serves recipes only), `S07-6-180-162.png` (the manual second step replaces the review-from-manual state), `V-O05-200.png`, `33-addtomeal-from-food.png`, `09-add-to-meal-sheet.png` and `26-manual-discard-dialog.png`.
- Renderer: Playwright’s bundled Chromium (headless), `deviceScaleFactor: 2`, mobile emulation with touch. Enlarged text is injected as `html { font-size: 200% }`, the same mechanism the Storybook decorator uses. Safe-area variants use the Storybook fixture (59 px top / 34 px bottom at 393 × 852); the runtime reads `env(safe-area-inset-*)`.
- Capture rule (ledger D-14): while a dialog is open, and for the keyboard-inset fixture, the capture is the viewport; every other capture is full-page. A full-page capture of a page taller than the viewport shows the **fixed navigation bar and sticky headers/footers at their scroll-0 position, i.e. mid-image** — a screenshot artefact, not a layout defect; at runtime the bar is fixed to the real viewport bottom (ledger D-26) and the content reserves its height once.
- Regenerate: `npm run build && npx vite preview --port 4173`, then `node scripts/verify/runtime-walkthrough.mjs`; `npm run build-storybook`, then `node scripts/verify/storybook-captures.mjs`. Both scripts fail on console/page errors; the Storybook script also fails when a story’s play function throws.
- Superseded evidence: the previous curated sets (rendered from `97905ad`, tracked at `e229cbe`; the Stage A set tracked at `a789d10`) were replaced file-for-file once each replacement had been inspected; git history holds them.

## Observations kept as limitations

- Full-page captures place the fixed bar and sticky bars mid-image; the runtime keeps them at the viewport edges.
- The radio mark in photo suggestions keeps its 24 px size at 200 % text; the row target grows with the text.
- No real screen reader, device, native safe-area or live software keyboard was exercised.
- The midnight rollover was exercised with Playwright's mocked clock and the day boundary by rewriting the stored record's day key; a real overnight session was not observed.
- The lazy thumbnails of hidden mounted screens never load, so the runtime capture helper waits (bounded) only for the visible screen's images.
- The week strip is a horizontal scroller by design at 320 px and at 200 % text; its previous/next-week and Today buttons are the keyboard path, so the overflow assertion ignores scroll containers that fit their parent.
- The browser-Back guard was exercised with Playwright’s `goBack`; a refresh or tab closure with a changed draft gets only the browser’s generic prompt (ledger D-52), and native swipe gestures were not exercised.
- The two Storybook runs that ran concurrently with a build or the walkthrough showed load timeouts; the counted runs are the isolated ones recorded in the ledger §12.7 and §13.7.
- The day strip’s mouse drag is exercised only by hand (the walkthrough and stories use taps, keyboard and native scrolling); the featured recipe is deterministic (the first flagged, photographed recipe that matches), so no "Recipe of the day" is claimed.
- The estimate path is verified against the report’s own worked example and the equations transcribed in `docs/ux/targets-and-estimation.md`; no real person’s requirement is asserted, and the gain goal produces no surplus by design.
